# Cyber DM

面向 PC 和手机浏览器的 AI 语音剧本杀。Web 版优先，原生客户端为后续优化项。

## 开发状态

已实现原创短本、任选角色、阶段／搜证／投票引擎、角色上下文过滤、实时角色对白生成与独立主持审核、会话文件持久化、响应式页面及服务配置界面。支持 Chat Completions、Responses、Anthropic Messages 三种模型协议适配。

首版为一名真人任选角色，其余角色和 DM 由 AI 扮演；多人真人房间列为后续能力。

**目前不是满足最终验收的版本。最新即时对白、主持调度和分组私聊流程尚未通过部署后的新整局真实语音验收。** 已实现浏览器麦克风 PCM 采集、灵矽 WebSocket 桥接、下行 Opus 解码、第三方 SSE 回调及 PDF／文本解析草稿流程，但尚未连接真实设备完成手机语音实测。已加入音色目录读取、默认分配、原生灵矽音色 ID 播放、参考音频上传与复刻训练界面，以及可选访问口令认证；平台目录和原生 WebSocket 音色切换已用公开 API 响应及模拟链路验证，真实设备仍需账号侧绑定。

上传支持结构化 JSON，以及 PDF／UTF-8 TXT／Markdown；剧本馆可以一次选择多个文件，也可以直接选择整套剧本文件夹，系统会逐个接收并跳过海报、音频等售后素材。非 JSON 文件使用配置的解析模型形成草稿，必须核对原文、角色知情范围、阶段、线索、台词和结局后发布；角色资料、阶段、事实、线索、台词和结局均需有可在原文中定位的引用，缺少或伪造引用会阻止发布。扫描 PDF 是正常的剧本资料格式：没有文字层的文件会在资料包中逐页 OCR，不会再因为扫描格式直接报错；OCR 结果只作为待审核材料，不能绕过引用校验。首次版本仅支持有投票和揭晓结局的完整推理本。

当前项目配置的 DeepSeek 官方 API 不能把 PDF 当作模型文件直接提交。DeepSeek 的 [Files API](https://api-docs.deepseek.com/guides/files_api) 目前只列出 JPEG、PNG、GIF 和 WebP；因此资料包会先读取 PDF 的文字层，只有扫描页才在浏览器中 OCR，再把带文件名和页码的文本交给解析模型。DeepSeek 网页端或第三方中转站提供的 PDF 上传能力不等同于官方 API；若以后配置支持 PDF 的 provider，可以再增加 provider 专用的原文件上传适配。

## 运行

需要 Node.js 22 或更新版本。

```sh
npm ci
npm run build
npm start
```

打开 http://127.0.0.1:3001 。开发时使用 `npm run dev`，Vite 页面代理至 3001 端口。

手机浏览器要使用麦克风，部署时必须通过 HTTPS/WSS。除反向代理外，也可以直接给服务端提供证书：`HOST=0.0.0.0 CYBER_DM_TLS_CERT=/path/fullchain.pem CYBER_DM_TLS_KEY=/path/privkey.pem npm start`；浏览器访问对应的 `https://` 地址即可。证书路径只从环境变量读取，不写入配置页面或仓库。

在“连接与声音”填写 provider（基地址应包含服务要求的 `/v1` 等前缀）、协议、模型 ID 和 API Key，然后为每个角色和 DM 分配服务。未配置不会伪装成 AI 响应。

设置页的“发车检查”会逐项显示剧本、解析模型、角色模型、角色音色和灵矽桥是否齐全；它只返回配置状态，不会显示或记录密钥。只有检查全部通过后，才建议进行语音整局验收。

剧本馆支持输入创作要求生成原创剧本草稿，也支持对已有剧本提出自然语言改编要求。两种结果都会进入人工核对区，核对角色知情范围、线索、台词和结局后才可发布；改编不会修改正在进行的房间，AI 生成内容不会被当作事实依据。

当前服务器仅监听本机。配置与会话保存在 `.data/`，不纳入 Git；密钥在本地文件保存并限制文件权限，尚未实现磁盘加密。当前配置页拥有本实例全部配置权限。远程验收需要设置至少 16 字符的 `CYBER_DM_ACCESS_CODE` 和准确的 `CYBER_DM_PUBLIC_ORIGIN`（本项目为 `https://cyber-dm.caotc.org`），再通过 HTTPS 反向代理访问。此口令是单用户实例访问保护，不是多人账号与房间授权系统。


测试覆盖角色秘密／私聊隔离、玩家与生成对白不写入事实、未知事实引用拦截、主持推进守卫、语音投票确认、私聊邀请／拒绝／过期、状态版本和取消回滚，以及每个可选角色到终局的路径。另有原文引用校验、文本提取与原创草稿、模型协议、访问保护、就绪检查和模拟灵矽服务测试，覆盖回调鉴权、会话绑定、去重、旧轮次失效、原生音色 ID、音色参数和默认分配。测试数量以当前 `npm test` 输出为准；本地测试不替代真实服务和移动设备整局测试。

`examples/after-hours.json` 是原创短本《闭馆之后》，包含完整事实与结局，玩家请勿提前阅读以免剧透。它也是当前结构化导入格式的示例。此首版引擎当前只支持以投票和揭晓结尾的推理本，其他机制尚未实现。

详细目标、预算、时间、技术边界与验收条件见 [需求与架构](docs/requirements-and-architecture.md)。

有域名时的 HTTPS 子域名、Caddy 反代、灵矽回调和真机验收步骤见 [HTTPS 部署](docs/deployment.md)。

## 灵矽联调准备

在“连接与声音”填写灵矽 API Key、WebSocket Token、Device ID、Client ID、Agent ID 与业务回调 Token，并为 DM 和所有 AI 角色绑定灵矽音色 ID。平台的第三方业务服务应指向：

```text
https://你的域名/integrations/linx/chat/stream
Authorization: Bearer 与界面配置相同的回调Token
```

此地址必须可由灵矽访问；浏览器到本服务需 HTTPS/WSS 才能在手机上使用麦克风。远程访问必须启用上文的访问口令，并由 HTTPS 反向代理保护；不要直接暴露无认证实例。设备绑定及第三方模式开通以账号实际权限为准。

进入房间后连接语音，由主持人开场并安排首轮发言。可启用“自动接话”：说完停顿约 1.8 秒自动发送，角色播放完再继续听；也可手动结束录音。播放时不会持续收音，切后台会关闭麦克风和连接，返回后需重新连接，游戏状态保留。不同麦克风、环境噪声及移动浏览器上的端点效果仍须真机验证。

- 阅读角色本：新房间先离线阅读本人设定与已知故事。点击“阅读完毕，连接语音并开始”一次完成阅读确认和语音连接，成功后才由主持人正式开场；阅读期不录音、不需要口头确认。未确认前不能搜证、投票或跳阶段，旧局保留原进度。
- 主持点名：DM 选择的 NPC 会在提问后自动依次回应，再由主持人明确交回真人，不需要玩家插话触发。
- 公开讨论：角色根据自己的当前知识和实际听到的对话即时组织语言，不从台词池挑一句应答。情绪、试探和标明不确定的推测允许自由表达；人物说法仍是证词，不会变成剧本事实。独立 DM 审核请求可读全本，演员生成请求不接收全本；模型审核不能保证语义零幻觉。
- 阶段与搜证：说“下一阶段”仅提出请求，由 DM 根据讨论和证据判断，代码守卫控制真正推进。说“搜查／我要搜查／查看＋完整线索名”按当前阶段权限搜证；不依赖玩家点击按钮切换阶段。
- 私聊：仅剧本当前阶段明确开放时可邀请，如“我想和周启、陈墨私聊”或“邀请周启私聊”。人数上限含真人玩家，邀请可按阶段策略被拒绝，房间到时结束；说“结束私聊／回到大厅”可主动返回。参与者之外的角色和 DM 不接收私聊原文。私聊使用语音，不提供任意文本私信；过期后的首句不会悄悄转为公开发言。
- 投票：在投票阶段说“我投周启／我投票给周启／我选周启”，主持人复述后另说“确认投票／确认”才提交，也可说“取消投票”。待确认投票有时限，期间其他操作会使其失效；全员投票完成后才揭晓。

语音协议假定上行 PCM、下行按 hello 协商 PCM 或 Opus。模型输出经过规则校验后返回 SSE；没有游戏回复的轮次不放行平台音频。平台对旧音频的取消顺序、多消息变声与音频完成反馈仍须真实联调验证。
