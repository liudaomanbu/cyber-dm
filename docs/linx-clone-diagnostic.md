### 真实上传发现的确定性存储缺陷

验证时本地 WAV 为 1,075,456 字节，公网返回却是 18,282,752 字节（17 倍）。原因是 `WorkersSqliteStorage.writeChunks` 对 Node Buffer 使用 `slice()` 后将 `.buffer` 写入 SQLite；Buffer 的 slice 是共享视图，底层 ArrayBuffer 仍包含整份上传数据。因此每个分块都写入了整份文件，下载后被重复拼接，小文件也可能包含缓冲池中超出视图范围的字节。

已改为将每个 subarray 精确复制到独立 Uint8Array 再持久化。新增回归测试涵盖缓冲池偏移、64 KiB 边界、1 MB 文件与迁移快照。构建与 151 项测试通过，部署版本 `9830efcf-3958-4114-8495-e60c51f534bc`。旧文件不会因代码修复自动恢复，验证使用保留的录音生成新 WAV 并重新上传；提交前比对完整字节与 SHA-256。
