# 灵矽 Web 语音身份与连接凭据

本项目的浏览器经 Mac 后端连接灵矽。平台所说的“设备”可以是软件语音客户端，无需额外购买硬件。

- **设备 ID**：后端语音客户端的固定身份，使用 MAC 格式。OTA 请求头 `Device-Id` 与请求体 `mac_address` 必须一致。当前项目使用基于本机网络硬件身份和客户端 ID 派生的独立伪 MAC，保存在本机配置。
- **WebSocket Token／设备连接 Token**：设备绑定智能体后，OTA 返回的 `websocket.token`，用于 WebSocket 的 Bearer 鉴权。
- **平台 API Key**：管理智能体、设备绑定、音色和复刻的凭据，不能直接当作上述 Token。
- **客户端 ID**：软件生成并持久保存的 UUID，OTA 和 WebSocket 使用相同值。
- **业务回调 Token**：本项目生成的独立凭据，用于验证灵矽发往游戏服务的请求。

## 获取步骤

1. 创建专用于项目的灵矽智能体。
2. 确定并保存设备 ID、客户端 ID。向 `https://xrobo.qiniuapi.com/v1/ota/` 发送设备上报；未绑定时返回六位 `activation.code`。
3. 在灵矽控制台绑定激活码，或使用已授权的平台 API 调用 `POST /xiaozhi/device/bind/{agentId}/{deviceCode}`。
4. 使用相同设备身份再次上报 OTA，获取 `websocket.url` 和 `websocket.token`。Token 保存在服务端，不输出到日志。
5. 以此身份建立 WebSocket、发送 `hello` 并检查服务端应答。这仅验证语音连接鉴权。
6. 另行配置第三方 Chat 业务回调及验证真实 ASR、角色回复和 TTS，才能验收语音整局。

## 当前采用的语音路线（2026-10-24 更新）

由于原生第三方 Chat 供应器的配置接口在实测中返回 404，当前实例使用官方支持的自定义 OpenAI 兼容模型入口：

1. 灵矽智能体绑定项目的 `cyber-dm-speech-only` 端点。这个端点只返回空完成，不运行模型、不转发平台历史，也不替代用户为角色选择的对话模型。
2. 每次录音建立独立的灵矽识别 WebSocket。其 STT 文字只交给这一轮绑定的游戏房间与私聊对象。结束录音保留这一轮；取消或下一轮使旧连接和结果失效。
3. 游戏仍通过每个角色独立配置的对话模型选择已审核台词。
4. 另一独立软件设备连接负责用角色音色合成这些台词。识别连接的所有音频都丢弃，避免平台的空完成或迟到消息干扰播报。

这不是新增一个收费的对话模型。两个设备是软件身份，无需硬件；识别和合成仍使用灵矽服务及其正常额度。首版每句合成完成后开始播放，首音延迟还可以继续优化。

设置脚本：`node scripts/configure-linx-speech.mjs`。先部署服务端路由，再运行脚本，完成后重启服务。脚本读取本地配置、核验公网端点、创建或复用专用配置、绑定并核验智能体与播报设备，凭据仅保存在 `.data`。脚本可重跑恢复；服务端通用设置保存不会覆盖自动管理的播报设备字段。

官方依据：[大语言模型 API](https://linx.qiniu.com/docs/xrobot/api/llm)、[LinxClaw 接入实践](https://linx.qiniu.com/docs/xrobot/guide/linxclaw-best-practice)。原生业务回调模式保留兼容，但不用于当前实例。

### 实际验证范围

- 2026-10-24：真实灵矽单句合成返回 104,364 字节 WAV，16 kHz 单声道，3.26 秒。
- 本机路径：将已知语音送入真实识别，得到“请介绍一下现在已经公开的线索”；游戏私聊 DM、调用已配置对话模型并更新会话；真实播报返回 119,680 字节 PCM，3.74 秒。
- 公网 HTTPS/WSS 路径：同一句语音私聊 `chen`，识别、游戏提交、独立角色音色合成成功，返回 69,760 字节 PCM，2.18 秒。
- 这些测试使用录制好的合成音频注入，与浏览器使用相同的语音 WebSocket 协议；不代表已经验证手机麦克风权限、扬声器实际听感或完整真人整局。

### 网页验收

刷新 https://cyber-dm.caotc.org ，必要时重新输入原访问口令。打开《闭馆之后》，选择玩家角色并发车。在语音房间点击“连接麦克风”，允许站点使用麦克风，再点击“开始说话”；说完点击“结束录音”。先测公开讨论，再切换私聊主持人或另一角色。页面应依次显示识别文字、游戏回复并播放对应音色。关键进度操作须再说“确认执行”。手机建议直接使用 Safari 或 Chrome 打开 HTTPS 地址。

## 开场播报与自动接话（2026-10-24 验收修复）

原实现只合成麦克风回合的回复，遗漏了主持人开场、文字输入和“请发言”按钮产生的事件。现已统一为按房间授权的事件播放队列：浏览器仅提交事件 ID，服务端从玩家可见的已提交记录取台词与角色，不能由浏览器任意指定秘密内容或其他房间。语音回复携带相同事件 ID，避免界面刷新再次播报。单项合成失败会提示并继续下一条；每条非玩家台词可点“重播语音”。首次连接会补播当前页面的角色台词；重连不自动重复本页面已请求过的台词，遗漏时可显式重播。

默认开启“自动接话”：本地麦克风 RMS 活动累计达到 300ms，随后静音约 1.8 秒即提交识别。角色音频实际播放完毕后延迟 400ms 恢复收音；播放期间不收音，避免回声。20 秒未检测到有效发言会暂停，连续发言最多 90 秒。它判断的是音量和停顿，不是句子语义；思考停顿长或环境嘈杂时可关闭，使用原手动结束按钮。点击“暂停语音”会停止本轮并暂停自动收音。

验收记录：52 项自动化测试通过；真实公网验证了 DM 开场、HTTP 按钮邀请周启/陈墨的台词均返回各自音色音频，重复事件同步无复读，主持人单条重播成功。手机真机和具体环境下的停顿阈值仍需用户体验验证。

## 连接后开场与主持人轮次（2026-10-24 后续验收修复）

新建房间现在以 `started:false`、空事件列表等待。浏览器获得麦克风并激活播放环境、建立语音桥后发出 `begin_game`；服务端先确认灵矽输出设备 `hello`，再调用事务化、幂等的 `GameService.begin`。开场前校验 DM 音色及所有非玩家角色的模型/音色绑定。握手失败、断开或取消不会先写开场。旧房间保留历史，缺省 started 的历史数据视作已经开始。

主持人开场同时声明玩家先说、其他角色依次发言的顺序。玩家公开发言后，服务端依次生成每个 NPC 的回应，穿插只包含流程信息的主持人点名，最后主持人接回并提示当前阶段允许的下一步。后一个角色只能看到此前公开的发言和自己的事实；私聊仍只触发指定对象。整轮取消或后续角色生成失败时，不提交半轮剧情；阶段不会自行解锁。

首次公开陈述优先使用剧本已有的 statement；后续选择避免无意义重复和强制 fallback。提示词要求回应最近的公开讨论与主持任务，但模型仍只能选择审核台词，尚不是无限自由对白。

实测证据 `.data/hosted-round-result.json`：公网新房间连接前事件数为 0；语音连接后生成开场与点名；测试音频自动提交后实际播报顺序为 DM → 周启 → DM → 陈墨 → DM，三个角色均返回 PCM。没有使用“请发言”按钮。验证时模拟音频代替真人麦克风，因此仍需真人体验自然度。复测完整开场请刷新页面后新开一局；继续旧局不会删除或重演已有历史。
